# ULPF Rule Specification

This is the authoritative definition of a **Parsing Rule** — the artifact produced by an analyst or the Local Rule Authoring Agent, validated deterministically, and executed by the Data Plane. 

---

## 1. Rule Identity

| Concept | Field | Notes |
|---|---|---|
| Logical rule | `rule_id` (UUID) + `name` | Stable identity, e.g. `cisco-asa`. |
| Version | `rule_versions.version` (int, monotonic per `rule_id`) | Immutable once created. |
| Human-readable pointer | `name@version`, e.g. `cisco-asa@2` | Used in UI/logs. |
| Rule hash | SHA-256 over the canonical JSON of the version's content | Ensures cryptographic integrity of the parser config. |

## 2. Rule Version Document Shape

```json
{
  "parser_type": "regex",
  "parser_definition": {
    "engine": "re2",
    "pattern": "<named-capture-regex>"
  },
  "field_mappings": {
    "source_ip": "src_endpoint.ip",
    "destination_ip": "dst_endpoint.ip"
  },
  "target_schema": "ocsf",
  "schema_version": "1.0",
  "required_fields": ["time", "src_endpoint.ip", "dst_endpoint.ip", "action"],
  "type_constraints": {
    "src_endpoint.ip": "ipv4_or_ipv6",
    "dst_port": "int"
  },
  "masking_policy": {
    "actor.user.email": "hash"
  }
}
```

### Supported Target Schemas
- **`ocsf`**: Open Cybersecurity Schema Framework (v1.0+)
- **`ecs`**: Elastic Common Schema (v8.0+)

### Supported Parsers
- **`regex`**: Fast standard regex matching with named capture groups.
- **`jsonpath`**: High-performance JSON key extraction.

## 3. Fingerprinting

Rules are bound to specific log formats using a structural fingerprint. 
- **JSON payloads:** Sorted structural key-set fingerprint.
- **Unstructured/text payloads:** Token-substitution structural signature (IP/TIME/NUM/HEX replaced, then remaining words replaced with token classes).

If a log arrives with a known fingerprint, it bypasses the LLM and is processed deterministically using the mapped Rule Version configuration.

## 4. Lifecycle State Machine

- `DRAFT`: The initial output generated by the LLM Authoring Agent.
- `PENDING_REVIEW`: A draft that has passed deterministic validation and is ready for human approval.
- `ACTIVE`: A human-approved rule actively processing logs in the data plane. (Only one active version is allowed per Rule ID).
- `DEPRECATED`: An older version of a rule that has been superseded by a new active version.
